# Offline possible-occupancy / certified-free fusion experiment

This is not the running map query. `sta_map_query` remains unchanged. The separate `sta_map_query_fusion` is for archived failure-snapshot comparisons, followed by independent contracts if requested.

Let the static physical occupied set be O. A sensor-derived whole-volume certificate F must satisfy F subset complement(O), conditional on all declared geometry, finite-angular-cell coverage, detection and pose/range error assumptions. For any possible-occupancy outer set G, removing F is sound: `(G minus F) intersect O = G intersect O`. Thus a complete query ball B contained in F may be classified free even if G intersects B. This is not point-ray free evidence, a timeout, a reduced margin, a reduced body, or a claim that a measured guard ball is certainly occupied.

The clone reuses the exact existing full-ball test and budgets. It evaluates observed frames even where possible guards overlap and records `observedWholeBallFree` and `possibleGuardConflict`. Only observed whole-ball certificates override possible guards. A launch prior alone cannot override a guard. Unknown rays, missing frames, body/FOV clipping and map-capacity failures still fail closed. No guard is deleted from the stored map.

This is valid only for the declared static environment. An old free certificate may become stale in a dynamic environment. Simultaneous validity of statistical 95%/3sigma envelopes is not established by this set identity. If a future source introduces certain-occupied constraints, or contradictory/error-unbounded measurements, those require separate consistency handling; they must not silently be treated as merely possible guards.

OctoMap's official primary documentation distinguishes free ray traversal (excluding the endpoint), occupied updates and unknown space: https://octomap.github.io/octomap/doc/classoctomap_1_1OccupancyOcTreeBase.html . OctoMap uses probabilistic occupancy fusion; its mature free-space update mechanism motivates retaining negative evidence, but does not prove this experiment's stronger conditional geometric certificate. The set-inclusion argument above is the mathematical justification specific to this experiment.

`sta_fusion_contract` supplies seven synthetic/adversarial checks, including possible guard overlap in truly observed free volume, unknown space, prior-only conflict, whole-body clipping, actual sphere occlusion, missing rays and capacity fail-closed. It has not been executed by this agent; MATLAB execution belongs to the primary session.

Important primary-source qualification: OctoMap `insertPointCloud` gives occupied cells precedence over free cells within a scan, explicitly to avoid floor holes from mutual deletion. `insertPointCloudRays` warns that discretization can delete occupied space. This experiment is therefore NOT an implementation of an OctoMap free-over-occupied recommendation. Its only justification is the stronger whole-volume conditional certificate and possible-versus-certain distinction above. A point-ray, probabilistic miss, or unbounded false-negative observation must never be substituted for that certificate.
